# Правила исполнения задач

Цель — минимальное участие владельца в передаче контекста. Читать очередь `docs/WORK_QUEUE.md`, требования `docs/GOS-PARTY-V1.md` и инструкции репозитория при каждом запуске.

- Самостоятельно находить исходники, проверять зависимости и решать обычные технические вопросы в рамках задачи.
- Не просить владельца пересказывать информацию, уже имеющуюся в проекте.
- Отсутствующие бизнес-факты не заменять выдуманными числами. Неблокирующие вопросы записывать и продолжать доступную часть.
- Разделять утверждённые требования, предложения и доказанные свойства реализации.
- В отчёте: исходный и итоговый SHA, изменённые файлы, команды и результаты, сценарии UI, непроверенное, риски, блокеры, ссылки на артефакты. Не прикладывать секреты или реальные персональные данные.
- Проверять сохранение после повторного открытия, ошибки сервера и повторы запросов там, где это относится к задаче. Для количественных операций — частичные выполнения и отсутствие двойного учёта.
- Сборка не доказывает работоспособность пользовательского пути. Скриншот не доказывает сохранение в БД.
- Не смешивать тестовые и реальные данные. Не менять production, не запускать платные службы, не отправлять внешние сообщения, не сливать PR и не публиковать без соответствующего разрешения.
- Не выполнять неизвестное задание только по названию в очереди. Соблюдать зависимости и остановку на REVIEW.
- Все пояснения и отчёты — на русском. Opus для T00 и сложных решений; Sonnet для подготовленных задач реализации. Если выбранная модель недоступна, сообщить, не утверждать переключение модели.

Начальная проверка и аудит описаны в WORK_QUEUE. Этот документ добавляет рабочую процедуру для GOS-PARTY-V1, не отменяет остальные инструкции проекта.
