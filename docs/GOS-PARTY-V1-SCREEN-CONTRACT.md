# GOS-PARTY-V1 — контракт экранов, действий и связей

Версия 1.2. Дополняет `GOS-PARTY-V1.md`. Обязательное критическое ревью: `GOS-PARTY-V1-REVIEW.md`, правила R01–R12 имеют приоритет над прежними формулировками этого контракта и картинками в указанных ими случаях. Статус: проектные правила для проверки владельцем, не описание работающего приложения. Новые решения не следует выдавать за ранее утверждённые бизнес-факты.

## 0. Главное — обязательные ограничения

1. Пользователь задаёт количество изделий. Материалы, расход ткани, закупки, финансы и маркетплейсы не являются условиями работы v1.
2. Источник истины — сохранённые сервером записи, не состояние браузера и не картинка. localStorage не заменяет БД.
3. Модель постоянная; заказ — конкретное поручение одному цеху; в заказе допускаются несколько моделей. Приёмки и отгрузки могут содержать части партий. Модель, партия и отгрузка не взаимозаменяемы.
4. План, фактический крой, сшито, отправлено, получено, проверено, годные и брак — разные величины. Не подменять одну другой и не складывать показатели разных этапов как остатки.
5. Автосохранение черновика не подтверждает операцию. Скачать PDF не значит передать цеху. Готово в цехе не значит получено. Связать брак с повтором не значит исправить.
6. Ввод по цвету × размеру обязателен для движения изделий. «Все цвета» — сводный просмотр, а не допустимое место для неоднозначного ввода факта.
7. Исправленные изделия не считаются новым производством. Связь с исходной партией сохраняется навсегда. Замена новым изделием — отдельный сценарий.
8. Результаты одной операции сохраняются атомарно. Повторы запросов и одновременные действия не создают дубли и отрицательные остатки.
9. Любая подтверждённая операция имеет автора, дату, идентификатор и историю корректировок. Не удалять историю ради исправления числа.
10. После успешного сохранения затронутые экраны перечитывают актуальные данные. При ошибке не показывать «Сохранено», не обнулять форму.
11. Сохранять company_id, права и изоляцию файлов. API проверяет доступ независимо от скрытых кнопок UI.
12. Никаких вымышленных реальных данных «Стеганки». Цифры 1000/900/100 — только пример для тестовой среды.

| Автосохранение | Только черновик, с состояниями «Сохраняем», «Сохранено», «Не сохранено — повторить»; существующую запись обновлять, не создавать заново |

| Конфликт изменений | Не затирать более свежую запись; показать необходимость перечитать/сопоставить изменения |

Текстовые поля имеют длины и серверную валидацию. Количества — целые неотрицательные; пользовательский ввод 0 отличается от неизвестного пустого значения. Ячейка с нулём не создаёт движение. Размеры и цвета не вводить повторно свободным текстом в каждом документе.

## 3. V01 — Сегодня

### A01. Рабочая главная

- «+ Заказ на пошив» → A02, пустой черновик без фиктивных выбранных данных.
- «Внести крой» → конкретный заказ и задание, форма B04. Цех/модель/план подставлены.
- «Открыть» у пошива → заказ, вкладка Пошив. Дней осталось вычисляется из срока; просрочка показывается явно, дата сама не подтверждает готовность.
- «Открыть модель» у брака → D01 с фильтром открытого брака.
- Строка последних заказов → B01 по ID заказа, не поиском по названию.
- «Все заказы» → список с фильтрами цех/модель/активность и ссылками на штабы. Фильтры не изменяют данные.
- У задачи видны источник и дата обновления. При отсутствии сведений писать «Нет обновления», не угадывать готовность.
- Задачи выводятся из фактов: передано на крой и нет полного факта; просрочен пошив; получено и есть непроверенные; есть открытый брак. Не создавать вторую независимую копию статусов.

Проверка: после ОТК появляется открытый брак по исходной модели; после его полного разрешения напоминание исчезает; чужие заказы другой компании недоступны.

## 4. V01 — Новый заказ

### A02. Поля и кнопки

| Поле/действие | Источник, сохранение, связь |
|---|---|
| Цех | Справочник цехов; обязательный для готового заказа. + Добавить цех создаёт реальную запись, а не строку только в браузере |
| Модель | Каталог; + Добавить модель открывает A03. Несколько моделей — повторяемые блоки позиций |
| Размерная сетка | Шаблон модели. Пары 48–50 и т.д. — отдельные значения. Смена сетки после ручного ввода предупреждает о перераспределении |
| Цвета | Сохранённые цвета/варианты модели; + Добавить цвет. Удаление выбранного цвета с количеством требует подтверждения пересчёта |
| Количество | Ввод по каждому цвету; сумма модели и заказа вычисляется. Общий итог не конкурирует со вводом по цветам |
| Источник данных | «Шаблон модели» или выбранный прошлый заказ этой модели. Копируется план/настройки, не факты, статусы, PDF, приёмки и ID операций |
| Шаблон распределения | Выбор долей размеров или ручной режим; редактор долей и «Сохранить шаблон» |
| Матрица цвет × размер | Предварительный результат, ячейки редактируемы. Ручное изменение переводит распределение в ручной режим |
| + Добавить модель в заказ | Новый блок модели с собственными цветами/размерами/сроком; один и тот же SKU не дублировать скрытно |
| Сохранить как шаблон | Имя и область шаблона, сохраняются только повторно используемые настройки. Не подтверждает заказ |
| Сохранить черновик | Допускаются неполные данные; после входа доступно продолжение того же черновика |
| Создать заказ | Требуются цех, минимум одна модель, варианты и положительное итоговое количество. Сохраняет один заказ с позициями, затем открывает B01 |

Числовой пример: цвет Петроль 600, Чёрный 400, доли 12,5/25/25/25/12,5. Результат 75/150/150/150/75 и 50/100/100/100/50. Итого 1000. Целочисленное округление — метод наибольших остатков, при равенстве порядок сетки. Алгоритм работает отдельно по цвету, сумма сохраняется. Доли должны дать 100%. Если ручные ячейки не совпадают с заданным итогом цвета, нельзя молча исправлять итог: показать расхождение и предложить явное согласование.

### A03. Быстрое создание модели

Название обязательно; артикул, фото, размеры и цвета можно дополнить. Возможность начать черновик без фотографии обязательна. «Сохранить и выбрать» создаёт одну модель и возвращает её ID в A02. Повторное открытие каталога показывает ту же запись. Закрытие формы не создаёт пустую модель.
Уже переданные документы и план заказа не переписываются от последующего изменения справочника. Архивные записи сохраняются в исторических заказах; не предлагать их для нового выбора по умолчанию.

Проверки V01: создание записи на месте, отмена без потерь, перезагрузка черновика, повтор POST без дубля, неверные доли, количество 1/7/1001 при округлении, два цвета, две модели, недоступный цех, ошибка сохранения и конфликт двух вкладок.

## 5. V02 — Штаб заказа

### B01. Обзор

Заголовок: номер, цех, состояние; модели с фотографиями при наличии. Для нескольких моделей сводка по каждой, действия адресуются выбранной модели/заданию, не всему заказу без разбора.
Постоянные вкладки: Обзор, Крой, Пошив, Приёмки и ОТК, Документы, История. Физические перемещения доступны в приёмках и связанных отгрузках, без дублирования сущностей.
Показывать план и факты отдельно, сроки и рекомендуемое следующее действие с причиной. Полоса этапов — навигация по фактам, не команда сменить статус и не запрет параллельных этапов. При частичной сдаче пошив и ОТК могут быть активны одновременно.
«Редактировать план» для ещё не переданного задания; после передачи — явная новая редакция/дополнительное задание, с причиной. «История» показывает документы, операции и коррекции, а не только последнюю запись.

### B02. Задание на крой

1. Из штаба выбрать модель и объём этого задания; по умолчанию предложить ещё не назначенный объём, показать уже выданный. Докрой — отдельное задание со связью с заказом.
2. «Шаблон» предлагает настройки заказа; изменение не переписывает ранее переданные задания. Перекрой сверх заказа требует явного изменения плана или зафиксированного разрешения, не молчаливого повторного назначения.
3. «Все цвета» показывает сводку. «Разбивка по цветам» раскрывает матрицу и итоги. Любое редактирование объёма выполняется по конкретным вариантам.
4. «Сохранить шаблон» сохраняет доли с именем, не меняет весь каталог задним числом.
5. «Скачать задание PDF» создаёт/возвращает PDF выбранной сохранённой редакции. Документ содержит номер задания, заказ, модель, цех, дату, цвета, размеры, количества, единицу учёта и примечание. Без норм ткани и без геометрии лекал.
6. «Передано на крой» фиксирует дату фактической передачи и редакцию задания. Не отправляет сообщение цеху автоматически. Повтор кнопки не создаёт новое задание.

### B03. Файл и версии

Перед генерацией сохранить черновые данные. Если сохранение не удалось, не выпускать файл с неподтверждённым содержимым. После успешной генерации сохранять связь с заказом/заданием, автором, версией данных и шаблоном. Повторное скачивание отдаёт ту же версию. Новая редакция — новый документ, старый доступен в истории. Ошибка генерации имеет «Повторить», не обнуляет исходные данные.

### B04. Фактический крой

Выбрать задание, дату, конкретные цвета/размеры. План рядом, факт изначально пустой. Вводится количество этой сдачи, а не перезаписывается накопленный итог; подпись «Добавить результат кроя» и отображение «Ранее / сейчас / всего» обязательны.
Указать признак «Это окончательный результат задания» для отделения частичного кроя от завершённого с недокроем. Это предлагаемая детализация, не факт существующего UI. Факт больше плана допускается только с явным предупреждением и причиной: реальный результат нельзя скрывать; план не меняется автоматически.
«Сохранить факт» записывает результат без обязательного начала пошива. «Подтвердить крой и начать пошив» — составная операция: проверяет факт, дату старта и срок, сохраняет целиком; при ошибке ни одна половина не считается выполненной. Оба действия используют единый механизм факта, без повторного учёта.

### B05. Начать пошив

Дата фактического старта, длительность по умолчанию 15 календарных дней (предлагаемый вариант, уточнить при необходимости), ожидаемая дата вычисляется и может быть изменена явно. Начало от частичного кроя разрешается для соответствующей части. «Начать пошив» не означает, что все заказанные изделия уже раскроены.
Срок можно изменить с причиной/историей. Смена срока не создаёт дополнительное производство.

Проверки V02: точный PDF, повтор скачивания, новая редакция, два задания без двойного распределения, частичный крой, недокрой, перекрой, исправление факта после последующих операций не ломает баланс, план остаётся неизменным.

## 6. V03 — Пошив, отправка и получение

### C01. Пошив и готовность

«Записать готовность» — дата и количество по вариантам, сообщённое цехом, источник/примечание при необходимости. Показывать ранее готовое и новую порцию; исключить смешение накопленного итога и добавления. Готовность не создаёт складской остаток фулфилмента. Цифра «раскроено» не автоматически превращается в «сшито».
Для отправки предложить подтверждённое готовое, ещё не отправленное. Если готовность ранее не записана, форму можно дополнить её подтверждением, но не создавать факт скрытно.

### C02. Отправить на фулфилмент

Выбор существующего фулфилмента/локации, «+ Добавить» с сохранением; дата, строки SKU, количество, при необходимости номер накладной/примечание. Итог рассчитывается.
«Подтвердить отправку» создаёт одну отправку с источником, назначением и ссылками на партии. Количество становится «в пути», не «получено». Проверка доступности и фиксация выполняются атомарно. Транспортный документ формировать только если шаблон реализован; не обещать автоматическую накладную из декоративной подписи макета.
Частичная отправка оставляет остаток у цеха. Отмену подтверждённой отправки выполнять отдельной коррекцией с проверкой отсутствия последующего получения.

### C03. Получение на фулфилменте

Выбор конкретной отправки; план отправки подставлен, фактически полученное вводится по вариантам и дате. «Подтвердить получение» добавляет событие получения и непроверенный остаток. Не превращать полученное в годное без ОТК.
Повторная порция получения ограничена неучтённым остатком отправки. Недостача остаётся в расхождениях; для закрытия недоставленного нужна явная причина, не автоматическое списание. Неожиданный товар/пересорт фиксировать отдельно и требовать согласования, не подменять SKU.

## 7. V03 — ОТК

### C04. Проверить изделия

Выбор полученной партии, места проверки и порции; доступны только ещё не проверенные изделия либо явно выбранные изделия, вернувшиеся из ремонта. По вариантам вводятся проверенное и дефектное количества, годные вычисляются: проверено минус брак. Количество не больше доступной порции. Пустое поле брака не означает ноль; есть явное действие «В проверенной порции брака нет». Непроверенное считается системой.
Для брака: количество, тип/причина из справочника (+ Добавить), заметка, необязательные фото, текущее место. Если одно изделие имеет несколько дефектов, число дефектов не должно увеличивать число дефектных изделий; модель записи должна это учитывать.
Вариант решения «Исправить со следующей партией» оставляет открытый брак. До подтверждения все показатели — предпросмотр.
«Подтвердить ОТК» одной транзакцией сохраняет проверку и классификацию. Отдельной кнопки, повторно начисляющей брак, нет. «Создать отгрузку» доступна после успешного подтверждения и только для годного доступного остатка.
После сохранения обновляются штаб, Фулфилмент, Модель и Сегодня. Ошибка файла фото не должна притворяться успешным прикреплением; правила обязательности фото не выдумывать.

### C05. Отправка в Москву — дополнение без отдельного макета

«Создать отгрузку» открывает форму с исходной локацией и доступными годными SKU, включая партии разных заказов при явном выборе. Указать место назначения и количества. Для v1 простой черновик не резервирует и не списывает товар. Подтверждение атомарно перепроверяет доступность; конкурирующая отгрузка получает конфликт, не отрицательный остаток. Если существующая архитектура требует явного резерва, сначала обосновать его в T00 и определить освобождение по R10.
«Подтвердить отправку» перемещает из источника в состояние «в пути». «Подтвердить получение» отдельно зачисляет фактически полученное в назначение. Не зачислять в Москве автоматически при отправке. Документы экспорта и интеграции перевозчика не включать в v1 по собственной инициативе.

Проверки V03: 1000 получено → 600 проверено (550 годных,50 брака),400 непроверено; вторая проверка400 (350 годных,50 брака) → итог900/100/0. Отправка900 исключает их из доступного остатка источника. Два параллельных запроса не могут отправить 1800. Повтор ОТК не начисляет ещё900/100.

## 8. V04 — Модель и её партии

### D01. Карточка модели

Постоянные название, артикул, фото, единица учёта, сетка и варианты. «Редактировать» меняет карточку, не исторические версии документов/заказов.
Вкладки: Партии, Размеры и цвета, Шаблоны, Брак; добавить доступ к связанным спецификациям без дублирования их записей.
- «Партии»: строки заказ/цех/план/принято годных/открытый брак, ссылка на штаб. Сроки и состояние показывать по модели, а не автоматически копировать сводный статус заказа.
- «Размеры и цвета»: поддержка каталога вариантов; нельзя разрушительно удалить используемый вариант. Архивирование сохраняет историю.
- «Шаблоны»: просмотр, создание именованной версии, редактирование будущих настроек; существующие планы не пересчитываются.
- «Брак»: открытые позиции с исходным заказом, SKU, количеством, местом, решением, связанным исправлением. Ссылка на исходное ОТК.
- «Годных на фулфилменте»: текущие физические годные в выбранном месте; отдельно показать резерв и доступно. После отгрузки900 карточка станет0, а исторически принято останется900.
- «Брак на фулфилменте100» и «Ожидает исправления100» могут описывать одни изделия, их нельзя суммировать в200.
- Меню «…» содержит только явно реализованные действия; не создавать фиктивные работающие кнопки.

### D02. Возврат в цех

«Оформить возврат в цех» открывает выбор дефектных SKU и количества, источник, цех назначения, дату. Можно вернуть часть. До отправки брак остаётся на фулфилменте; после отправки — в пути; после подтверждённого получения — в цехе. Во всех состояниях остаётся браком, недоступным к обычной продаже.
Цех выбирается с учётом исходного заказа, но фактическое место не угадывается. Если исходный цех другой, показать это явно; не переносить его обязательства автоматически на нового подрядчика.

### D03. Повторить заказ

«Повторить заказ» открывает A02 с сохранёнными характеристиками модели и возможностью выбрать источник настроек. Новый заказ получает новый ID; факты исходного не копируются.
Поле «Новый пошив» относится только к новым изделиям. Блок «Исправления прошлых партий» показывает доступный открытый брак той же модели с разбивкой по исходным партиям и SKU.
Чекбокс «Добавить100» выбирает количество к связыванию; доступны частичные значения. Не разрешать повторно привязать те же100 к двум активным заданиям ремонта. До сохранения это предварительный выбор.
«Создать повторный заказ» атомарно сохраняет новый заказ и назначения исправлений. Итоги отдельно: новый пошив1000; ремонт100; ожидаемая сдача1100. Крой только1000. Место хранения100 не меняется от чекбокса.
Снятие ещё не исполненной связи освобождает назначение ремонта, не закрывает исходный брак. При исполненном ремонте изменения проходят через коррекцию.

### D04. Получить исправленные изделия

При сдаче цехом выбрать происхождение: новое производство или ремонт с ID исходной партии. Если в одной отправке1100, сохранять две группы происхождения, даже при одинаковом SKU.
Повторный ОТК100: например80 исправлены,20 снова дефектные. Открытый брак исходной партии уменьшается только на80;20 остаётся. Историческое первое выявление100 остаётся в истории.
Годные80 добавляются к текущему доступному остатку в месте приёмки, а не автоматически в Москву и не к выпуску новых1000. Ремонт не должен создавать повторный производственный приход той же физической единицы.
Невозможность ремонта: отдельное решение владельца о списании/замене; не закрывать долг автоматом. Финансовую компенсацию не реализовывать без нового задания.

Проверки V04: перенос100, перенос40 из100, два одновременных назначения, возврат частями, повторный дефект20, смена следующего заказа до ремонта, старый брак без следующей партии, повторный заказ без старых фактов.

## 9. Спецификации — обязательное дополнение

### E01. Реестр

Раздел Спецификации: номер, модель, заказ при наличии, версия, состояние, дата; поиск/фильтры; открытие одного документа из списка, модели и штаба ведёт к одной записи.
«Создать спецификацию» позволяет выбрать модель/заказ. «Создать из модели»/«Создать из заказа» подставляет контекст. Исторические документы доступны независимо от архивирования модели.

### E02. Редактор и PDF

- Использовать подтверждённый эталон; сначала найти текущий генератор и шаблон. Не придумывать юридические формулировки, обязательные поля, номера или подписи.
- Поля получают данные из модели и заказа с обозначением источника. Правки конкретной спецификации не должны молча менять каталог.
- «Сохранить черновик» сохраняет данные без фиксации версии для производства.
- «Предпросмотр» показывает документ по сохранённому снимку. Изменение данных после предпросмотра требует обновления предпросмотра.
- «Подтвердить версию» фиксирует снимок полей и версию шаблона; если генерация не удалась, явно показать «PDF не сформирован» и не считать файл доступным.
- «Скачать PDF» отдаёт конкретную сохранённую версию. «Новая редакция» копирует в новый черновик, не перезаписывает старый.
- «Связать с заказом» указывает точную версию. Замена версии после начала работ явная, с историей. Она не изменяет количество кроя задним числом.
- Не делать спецификацию обязательной блокировкой запуска, пока состав эталона и это правило не согласованы.

Проверки: кириллица, фото, длинные названия, несколько страниц, размеры/цвета/итоги, доступ к сохранённому файлу после перезахода, стабильность старой версии, отсутствие доступа другой компании.

## 10. Связи для кода и БД

Это логические отношения. Физические таблицы, поля, маршруты и компоненты Claude обязан сопоставить с существующим кодом в T00, а не создать второй независимый учёт.

| Источник | Связь | Получатель |
|---|---|---|
| Компания | владеет и изолирует | Все доменные записи и файлы |
| Модель | имеет | Варианты цвет×размер, шаблоны, версии спецификаций |
| Заказ | назначен | Одному цеху |
| Заказ | содержит | Позиции моделей и план по вариантам |
| Позиция заказа | использует | Зафиксированные требования/версию спецификации |
| Задание на крой | относится | К заказу/позиции и вариантом плана |
| Факт кроя | исполняет частично/полностью | Конкретное задание |
| Готовность пошива | относится | К позиции и вариантам, отдельно от кроя |
| Строка отправки | хранит происхождение | Партия и вариант; для ремонта исходная партия и назначение ремонта |
| Получение | ссылается | На отправку и её строки |
| ОТК | проверяет | Конкретный полученный/возвращённый из ремонта объём |
| Брак | сохраняет | Исходное ОТК, партию, SKU, текущую локацию и открытое количество |
| Назначение ремонта | связывает | Открытый брак и следующий заказ/сдачу, не меняя происхождение |
| PDF/фото | связан | С моделью, заказом, спецификацией/операцией через существующий механизм документов |

Состояние производства, качество и местонахождение независимы. Сводный статус заказа — производное представление, не единственное поле, управляющее всем.
Потребуются операции с явными контрактами ввода/вывода, атомарностью, идемпотентностью, правами и проверкой версии записи. Точные названия API утверждаются после аудита; не выдавать предлагаемые endpoints за существующие.

## 12. Контрольный проход владельца

Каждая строка: НЕ ПРОВЕРЕНО / ПРОЙДЕНО / ОШИБКА, ссылка на доказательство. Изначально все НЕ ПРОВЕРЕНО.

| Проверка | Ожидаемый результат |
|---|---|
| Создать Стеганку в заказе | Модель видна в каталоге после перезагрузки |
| Добавить цех/цвет/сетку | Сохранённые записи можно выбрать снова |
| Два цвета600/400 | Итог1000, размерные суммы125/250/250/250/125 |
| Добавить вторую модель | Сохраняется в том же заказе с отдельными параметрами |
| Оставить черновик и вернуться | Ввод не потерян, производство не запущено |
| Создать и открыть заказ дважды | Один заказ, те же данные |
| Скачать задание | Размеры, цвета, количества совпадают с сохранённой редакцией |
| Передать задание и повторить запрос | Одна передача |
| Внести крой частями | Накопленный факт правильный, план прежний |
| Внести срок15 дней | Видна ожидаемая дата, готовность не появляется сама |
| Отправить1000, получить600+400 | В пути уменьшается до0, непроверено1000 |
| ОТК600 затем400 | Итог900 годных,100 брака,0 непроверенных |
| Отправить900 в Москву | На исходной локации доступно0, в пути900, брак100 на месте |
| Повторный заказ1000 + ремонт100 | Новый крой1000; связь старого брака сохранена |
| Повторное ОТК ремонта80/20 | Открытый брак20, годных прибавилось80 в месте приёмки |
| Изменить модель после PDF | Старый PDF неизменен |
| Ошибка/повтор/две вкладки | Нет дублей, отрицательных остатков или ложного сохранения |

Для нового пользователя пустые состояния должны вести к созданию первого заказа; для телефона формы должны оставаться работоспособными, но отдельный мобильный дизайн ещё не отрисован. Сквозной тест выполнять на отдельной тестовой компании/БД, не создавать примерную Стеганку в production.

## 13. Открытые решения и границы обещаний

- Реальные данные Стеганки и единица учёта нужны от владельца; костюм на макете не доказывает, что Стеганка комплект.
- Эталон PDF и его поля должны быть найдены/подтверждены. Его оформление не реконструировать по догадке.
- Требование обязательной спецификации до передачи, правила разрешения перекроя, сроки ремонта и отмены не были окончательно заданы владельцем. Предложенные безопасные варианты выше не выдавать за прежние договорённости.
- Отдельно уточнять материальную замену брака; ремонт существующего изделия поддерживается основной цепочкой.
- Макеты статические, кнопки в изображениях не работают. Тестировать интерфейс можно только после реализации либо создания отдельного интерактивного прототипа.
- Код, БД и production этим документом не изменены. Этот контракт не разрешает публиковать приложение, мигрировать рабочую БД или отправлять документы цеху.
