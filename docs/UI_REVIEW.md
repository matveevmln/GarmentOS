## 1. Что реализовано

### 1.1 Инженерный фундамент (`docs/UI_FOUNDATION.md`, полностью)

- Tailwind CSS v4 (CSS-first, `@theme` в `Tokens/tokens.css`) — единственный источник токенов: цвета, радиусы, тени, типографическая шкала, z-index, длительности анимаций. Ни одного значения, продублированного в двух местах.
- shadcn/ui-паттерн (копия исходного кода в `apps/web/src/design-system/`, не пакет из node_modules) поверх Radix UI (`radix-ui` — унифицированный пакет) + `class-variance-authority` + `tailwind-merge`/`clsx` (`cn()` в `design-system/utils.ts`).
- Полный набор фирменных токенов переносит палитру `apps/prototype` дословно — ни одного дефолтного shadcn-серого/синего цвета в интерфейсе.

### 1.3 Форма-эталон: `ProductionOrdersPage`

Полностью перестроена на новых компонентах (`Card`, `Button`, `Input`, `Select`, `DatePicker`, `Avatar`, `SkeletonList`, `toast`) — это образец, по которому будут построены остальные 7 форм после утверждения. Ключевые изменения относительно старой версии:
- Поле «Срок сдачи» — `DatePicker` с русской локалью вместо нативного `<input type="date">` (формат `mm/dd/yyyy`, нечитаемый для русского пользователя).
- Ошибки — `toast.error(...)` с понятным текстом вместо инлайн-текста красным по странице.
- Успех — `toast.success(...)` вместо молчаливого обновления списка.
- Список результатов — `Card` + `Avatar` вместо `<div class="card list-card">`.

| Было | Стало |
|---|---|

## 3. Что осталось (сознательно не сделано в этом проходе)

1. **7 экранов не мигрированы на новые компоненты формы.** `WorkshopsPage`, `SuppliersPage`, `MaterialsPage`, `WarehousesPage`, `ProductsPage`, `ProductDetailPage`, `PurchaseOrdersPage` — у них обновлены только пути импорта после переноса файлов в `design-system/`, сама вёрстка форм/списков ещё на нативных `<select>`/`<input>` и старых CSS-классах. Это осознанное следование указанию владельца проекта: сначала утвердить форму-эталон, потом переносить остальные — не начато до этого утверждения.
2. **Tier B компоненты не построены** (`GarmentCommandPalette`, `GarmentBottomNavigation`, `GarmentFAB`, `GarmentTimeline`, `GarmentAIBriefing`, `GarmentActivityFeed`, `GarmentChart`/Recharts и др. из `docs/UI_FOUNDATION.md`) — ни у одного нет сегодня экрана-потребителя (принцип 3, эволюционная архитектура). Будут построены по мере появления конкретного экрана, который их требует.
3. **Undo (снек-бар после удаления) не реализован** — потому что в `apps/web` сегодня нет ни одной операции удаления ни на одном из 8 реальных экранов. См. `docs/UX_PRINCIPLES.md`, §6.
4. **Автосохранение форм не реализовано** — единственная многополевая форма сегодня (заказ пошива) сохраняется одним запросом; автосохранение отложено до появления формы, где это реально болит (см. `docs/UX_PRINCIPLES.md`, §7).
5. **Экраны, названные в запросе владельца проекта, но физически не существующие в `apps/web` сегодня**: Документы, Финансы, Профиль, Настройки, Меню, Карточка партии (баланс производственной партии). Они не были сфабрикованы как заглушки специально для этого ревью — показывать нечего, это честный текущий пробел, а не пропуск в проверке. Часть из них (Документы, баланс партии) описана архитектурно (`docs/DOCUMENT_ENGINE_ARCHITECTURE.md`, `docs/PRODUCTION_BATCH_LIFECYCLE_ARCHITECTURE.md`), но не реализована на уровне UI.
6. **Контраст текста не проверен автоматическим инструментом** (WCAG AA) — только визуальной оценкой палитры. Открытый пункт, зафиксирован в `docs/UX_PRINCIPLES.md`, §9.

## 4. Известные компромиссы

1. **DatePicker — визуальный артефакт.** В открытом календаре видны едва заметные круглые тени за цифрами дней (не описаны в react-day-picker v10 документации как штатное поведение темизации через `--rdp-*`). Функционально календарь работает верно: русская локаль, правильный фирменный красный акцент на стрелках навигации и «сегодня». Решено принять и задокументировать как известный, не блокирующий компромисс, а не продолжать отладку — стоимость дальнейшего расследования не оправдана для косметического дефекта такого масштаба.
2. **`styles.css` не переписан, а обёрнут.** Вместо полного переноса старых стилей в новую систему токенов, весь файл обёрнут в `@layer base { ... }` — минимальное вмешательство, разрешившее конфликт приоритета каскада (см. §5, найденный баг) без риска сломать 7 ещё не мигрированных экранов, которые всё ещё зависят от старых классов.
3. **Favicon отсутствует.** `/favicon.ico` — 404 на каждой странице (безобидно, не влияет на функциональность), не входил в объём этой работы, зафиксировано, чтобы не потерялось.

## 5. Найденные и исправленные критические баги (в процессе этой работы)

1. **CSS-комментарий самозакрывался.** В `Tokens/tokens.css` комментарий, описывающий паттерн `--color-*/--radius-*/--shadow-*`, содержал буквальную подстроку `*/`, преждевременно закрывающую блок `/* ... */` и ломающую весь последующий парсинг CSS (`vite build` падал с `CssSyntaxError`). Найдено подсчётом вхождений `/*` и `*/` в файле (8 vs 9). Исправлено переформулировкой комментария.
2. **Приоритет CSS cascade layers.** Кнопки `Select`/`DatePicker` рендерились сплошным красным фоном вместо белого/с рамкой. Причина: Tailwind v4 оборачивает свои утилиты в `@layer utilities`, и **любой** контент внутри `@layer` всегда проигрывает по приоритету неслоистому CSS независимо от специфичности селектора — старый `styles.css` содержал неслоистое правило `button { background: var(--accent); }`, перебивавшее утилиту `bg-card`. Исправлено оборачиванием всего `styles.css` в `@layer base { ... }` (то же имя слоя, что регистрирует сам Tailwind, с сохранением порядка `theme → base → components → utilities`). Проверено пересборкой + скриншотом.

Оба бага — не гипотетические риски, а реальные сбои, воспроизведённые и устранённые в процессе этой работы; упомянуты явно, а не скрыты, в соответствии с практикой проекта по видимой самокоррекции (см. `docs/ARCHITECTURE_REVIEW.md`, аналогичный случай с `marking_codes`).
