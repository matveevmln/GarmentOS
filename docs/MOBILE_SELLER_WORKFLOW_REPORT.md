# Реализация мобильного пути небольших партий — 2026-10-04

Основание: запрос владельца GarmentOS, один цех, небольшие партии, обычно приёмка целиком. Производственные данные владельца в тестах не использовались.

## Что изменено

- Навигация: Главная → Партии → Модели → Ещё. Спецификации доступны из истории модели и партии. Снабжение и Pilot не занимают рабочее меню.
- Один мастер: модель → количество по цветам и размерам → цена RUB/срок/цех → проверка. Цех автоматически выбирается только когда он один; несколько требуют явного выбора. Для готовой модели внутри мастера пять основных действий: Далее, Распределить по размерам, Далее, Далее, Разместить. Открытие, выбор модели и ввод чисел в этот счёт не входят.
- Новая или незаполненная модель подготавливается прямо в мастере: название, размеры, цвета. Технические артикулы формируются автоматически; уже существующие артикулы сохраняются. Фото и материалы не блокируют обычную партию.
- Ввод и текущий шаг восстанавливаются на том же устройстве. При потерянном ответе сохраняется точная попытка, которую можно повторить без дубля модели/партии. Явный выход удаляет этот локальный кеш.
- Партия, подтверждение, неизменяемый снимок условий и связанная спецификация сохраняются вместе. Черновик — отдельный явный вариант сохранения. Документ цеху автоматически не отправляется.
- Новый размер создаёт недостающие сочетания с существующими цветами. Исключённые размеры не попадают в новую автоматическую раскладку, но старые SKU и партии сохраняются. Список моделей читает настройки каталога, статистику партий — отдельно.
- Вместо бессрочного «Черновик» на модели показывается наличие размеров и цветов. Отсутствующее фото занимает компактное место. Модель можно убрать в архив и восстановить; архивная модель не используется для новых партий, её история сохраняется.
- Главная учитывает все незакрытые стадии, включая завершённый пошив, отправку и приёмку, ожидающую продолжения.
- Длинная приёмка на телефоне занимает полный экран. Факт предварительно заполнен по заказу с явным пояснением; перед сохранением требуется подтверждение сверки. Проверка качества остаётся отдельным шагом. Реальное место приёмки можно задать прямо при первой приёмке, оно сохраняется для следующих партий; отдельный раздел складов проходить не требуется.

## Проверки

На локальном PostgreSQL прошли 378 тестов всего проекта: 176 API, 193 доменных пакетов/схемы, 9 веб-клиента. Из API 26 — набор целостности, включая 8 новых регрессий мобильного пути. Проверены отказ между сохранениями, конкурентный повтор, изменение входа и автора, чужая компания, черновик, новый размер и архив. Lint и TypeScript всего проекта прошли; API и веб собраны. В локальной среде API собран прямым Nest CLI после сборки зависимостей: оболочка запасного pnpm не выполняет вложенный build-скрипт; CI использует закреплённый pnpm.

В Chromium при ширине 390 px и на ПК прошёл реальный сценарий: новая модель, потерянный ответ/перезагрузка/повтор, раскладка 9 изделий по трём размерам, блокировка несовпадения итогов, восстановление цены и срока, размещение при потерянном ответе без дубля и с одной спецификацией, приёмка фактически 8 вместо 9, сохранение незакрытой стадии после приёмки, архив/восстановление, следующая партия из модели, отдельный черновик. Всего 14 браузерных проверок; JavaScript-ошибок нет. Скриншоты и журнал — локальные артефакты `garmentos-repair-verification/mobile-workflow/`.

## Самопроверка итогового изменения

Проверены границы модулей и компаний, использование существующих сущностей, транзакции и порядок блокировок, сохранение использованной истории SKU, различие плана/факта/ОТК, и неоднозначный результат сети. Исправленные замечания: неполный импорт валидатора UUID; порядок очистки связанных тестовых данных; старые размеры в новой раскладке; размещение без восстановления точного запроса; доступ к первому месту приёмки после скрытия меню складов. Это самопроверка AI, не независимое человеческое ревью.

## Ограничения

Абсолютный минимум кликов и субъективное удобство владельца не гарантируются. Эмуляция телефона не заменяет проверку настоящей клавиатуры iPhone/Safari. Кеш живёт только в этом браузере; синхронизации черновика между телефоном и ПК нет. Два одновременно открытых мастера используют один локальный черновик пользователя — завершать следует одну партию за раз.

Физическое удаление моделей, удаление цветов из каталога, частичная приёмка, новая финансовая сверка и интеграции маркетплейсов в эту версию не входят. Для цветов существующей модели предусмотрено добавление. Детальные формы брака и переделок остаются прежними. Предложения документа MOBILE_SELLER_WORKFLOW_PROPOSAL.md, отсутствующие в перечне реализованного выше, не следует считать готовыми.

## Публикация

Подготавливается отдельная preview-версия и PR. После CI и проверки preview результат публикации будет указан здесь. Схема БД не меняется. Откат кода возможен на предыдущую успешную версию; созданные модель/партия/спецификация совместимы с прежней схемой и не удаляются при откате.
