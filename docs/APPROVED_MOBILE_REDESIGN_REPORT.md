# Реализация утверждённого мобильного макета

## Объём

Владелец утвердил концепцию и поручил выполнить весь описанный ремонт. Основные экраны переработаны по макету: компактный список, краткая карточка партии, горизонтальные фазы, одно закреплённое действие, меню ⋯, три вкладки и отдельный мастер с +/- и проверкой распределения. Фото показываются только настоящие, при отсутствии — нейтральный значок одежды. Шаги создания и введённые данные продолжают восстанавливаться с безопасным повтором исходного запроса.

Тумблер приёмки/закрытия удалён из общей карточки. Сервер отдаёт допустимые действия с учётом действительных прав и доменных инвариантов; guards остаются на изменениях. Стандартные права global owner/director восстанавливаются отдельно по ADR 0003. Рабочие партии, роли сотрудников и индивидуальные роли не меняются.

Переход «Изделия готовы» использует уже разрешённый доменом переход в ready_for_pickup. Это не выдуманный промежуточный факт: пользователь явно отмечает готовность к передаче, существующий жизненный цикл и его таблица не меняются. Изменение этапа пишется в аудит в одной транзакции; история показывает эти события и существующие факты отмены/закрытия.

Спецификация показывает мобильные строки без обрезки сумм. Для документа партии основная кнопка открывает именно эту партию. Для старого независимого документа сохранено распределение только доступного остатка; уже размещённые партии открываются по ссылкам. Обычная новая партия модели идёт через единый мастер.

## Проверки

Всего 379 тестов проекта: 177 API, 193 доменных/схемы, 9 веб-клиента. Новая регрессия проверяет реальные права/факты/чужую компанию. HTTP RBAC-тест проверяет capability owner и procurement_manager, затем реальный отказ отмены оператору.

На localhost PostgreSQL отдельно воспроизведён отсутствующий стандартный грант владельца: read-only аудит обнаружил 1 owner без отмены и 2 пропущенных гранта, исправление восстановило их, повтор ничего не меняет, company-specific роль owner осталась без изменений. Временные фикстуры удалены; скрипт запрещён для любого адреса кроме локальной тестовой БД.

28 проверок Chromium: восстановление формы и потерянные ответы без дублей; распределение и +/-; контроль итога; номер и одна связанная спецификация; фиксированное действие/три фазы/три вкладки; ширины 320/390/430, уменьшенная высота, реальная история этапа; приёмка 8 вместо 9; ОТК и закрытие; архив/восстановление; повтор модели; черновик; отмена owner; мобильная спецификация нового потока; старый документ и распределение остатка; настоящий оператор с ограниченными правами; desktop. Ошибок JavaScript нет. Артефакты: `garmentos-repair-verification/approved-redesign/`.

## Самопроверка

Проверены company-scoped чтения, серверные guards, существующие инварианты, неизменность истории SKU/партий, план/факт/ОТК, повтор после потерянного ответа. Выявленные и исправленные замечания: дублирующая кнопка в списке, уведомление поверх навигации, общий header в карточке вместо утверждённой композиции, неоднозначная доступная подпись сегмента прогресса, нецелые количества, старый фильтр specificationId, типизация HTTP-ответов теста. Ревью AI, не независимый человеческий аппрув.

## Ограничения и публикация

Эмуляция Chromium не заменяет настоящую клавиатуру iPhone/Safari. Формы проверены с уменьшенной высотой viewport; обработчик visualViewport учитывает клавиатуру. Черновик остаётся локальным для одного пользователя/браузера без синхронизации устройств. Физическое удаление моделей и обратная отмена фактической приёмки не добавлены; архив и контролируемое исправление этапа сохраняются. Полная приёмка партии — по подтверждённому сценарию владельца. Материалы/раскрой/условия доступны из дополнительных данных, на основном экране не занимают место.

Публикация выполняется в рамках прямого разрешения владельца в текущей задаче. CI, preview и результаты production будут зафиксированы в описании PR после проверки. В production не создаются тестовые данные и не используются реальные пароли пользователей.
