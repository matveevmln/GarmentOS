# ADR 0002 — одна попытка размещения небольшой партии

Статус: реализовано по запросу владельца от 2026-10-04; продолжает ADR 0001.

## Контекст

Владелец работает с телефона, одним цехом и небольшими партиями, обычно принимает их целиком. Отдельные формы заставляли повторять данные; старый мастер требовал материалы. Несколько независимых HTTP-сохранений за одной кнопкой могли оставить неподтверждённую партию или создать дубль после потерянного ответа.

## Решение

`POST /production-orders/place` композиционно вызывает существующие application-сервисы: создание черновика → подтверждение и неизменяемый снимок партии → спецификация из партии → запись завершённой попытки. Всё выполняется в одной `DatabaseTransaction`. Режим `draft` сохраняет только черновик. Внешняя отправка документов и генерация файлов в эту транзакцию не входят.

UUID попытки создаётся до запроса и сохраняется вместе с формой на устройстве, отдельно для пользователя и компании. PostgreSQL advisory lock по компании и UUID сериализует повторы между экземплярами API. Результат и SHA-256 нормализованного входа записываются в существующий append-only audit_log. Та же попытка с тем же входом и автором возвращает сохранённую партию; иной вход или автор получает 409. Журнал нельзя очищать независимо от бизнес-истории без пересмотра этой гарантии. Это использование существующего индекса истории сущности, без новой таблицы, миграции, очереди или системы событий.

Подготовка новой модели, её размеров и цветов также выполняется атомарно, с отдельным UUID попытки. Изменение размерного ряда создаёт недостающие варианты существующих цветов; использованные SKU сохраняются. Новая раскладка следует текущему размерному ряду, а при отсутствии настроенного ряда использует старые варианты как совместимый запасной путь.

Архив — существующий статус модели `discontinued`, восстановление — `active`; физического удаления нет. Создание партии и архив сериализуются по модели. Исторические партии доступны и для архивной модели. Прежний поток партий из спецификаций остаётся совместимым; редактирование документа не переписывает уже подтверждённые условия партии.

## Последствия

Форма переживает перезагрузку и может повторить сохранение после неопределённого сетевого результата. Для этого сохранённый вход блокируется до получения результата. Это локальный черновик конкретного браузера, не синхронизация между устройствами. При явном выходе кеш удаляется. Если браузер запрещает localStorage, интерфейс предупреждает о невозможности восстановления.

Обычная цена пошива остаётся RUB по существующему правилу; переделки и бесплатные операции используют прежний отдельный поток. Частичная приёмка не вводится. Новая таблица партий или параллельный каталог не создаётся.

## Проверка

Регрессии на настоящем PostgreSQL проверяют одновременные повторы, потерянный ответ, несовпадающий вход/автора, сбой спецификации, атомарную подготовку модели, принадлежность компании, синхронизацию размеров и архив. Браузерный сценарий действительно теряет HTTP-ответ после успешного сохранения и повторяет попытку после перезагрузки. Результаты — `docs/MOBILE_SELLER_WORKFLOW_REPORT.md`.
