# ADR 0003: допустимые действия партии и стандартные RBAC-гранты

## Контекст

Владелец утвердил переработку экрана партии. Старый UI показывал отмену без проверки реальных прав и маскировал приёмку переключателем «Завершён». Пользователь получил 403 после заполнения причины. Серверные guards и ограничения фактической приёмки сохраняются.

## Решение

Добавить read-only `/production-orders/:id/actions`: действительные права читаются через домен Identity, состояние — через ContractManufacturing, допустимость отмены/отката/приёмки/закрытия проверяется существующими доменными инвариантами. Ответ company-scoped, не даёт права выполнить изменение: на изменяющих endpoints сохраняются guards и повторная проверка.

Стандартные права отмены/отката должны соответствовать уже утверждённым миграциям 0033/0034: только глобальные owner/director. Для восстановления отсутствующего seed отдельный predeploy-скрипт проверяет и идемпотентно добавляет только эти два permission и только эти стандартные role_permissions, под advisory lock, в одной транзакции. Скрипт выводит агрегаты до/после без пользовательских данных; `--apply` обязателен для изменения. Не менять пользовательские роли, не выдавать право операторам, не обходить guard по роли из JWT. Новая схема/миграция не требуется: это исправление справочных данных.

## Последствия

UI не предлагает операции, которые сервер уже считает недоступными. Изменение прав между чтением и нажатием по-прежнему проверяет guard. Исправление seed проходит сначала в preview; обратная отмена приёмки не изобретается. Закрытие партии остаётся отдельным действием, принятая партия не считается закрытой.
