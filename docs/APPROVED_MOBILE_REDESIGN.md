# Утверждённый мобильный GarmentOS

Владелец утвердил макет с тремя экранами и поручил реализовать и опубликовать весь описанный объём. Макет — визуальный источник для новой композиции, не источник тестовых данных: фотографии, количества, даты и деньги берутся только из API.

## План / мастер-промпт реализации

1. Компактные светлые карточки партий: фото/нейтральный значок, модель, номер, цвет, статус, количество и срок, одна ссылка открытия. Удалить переключатель приёмки/завершения во всех местах использования карточки. Принятая партия остаётся незакрытой до явного завершения.
2. Карточка партии: назад, название, меню ⋯; краткая сводка 2×2; горизонтальные фазы Заказ → Пошив → Приёмка; короткая подсказка текущего действия; вкладки Размеры / Документы / История. Одна основная кнопка закреплена над мобильной навигацией. Остальные рабочие формы доступны по потребности, дополнительные данные — из меню, без длинной стены аккордеонов и неподключённых разделов.
3. Мастер: отдельный экран без нижней навигации/общей панели; четыре коротких сегмента прогресса, один шаг на экране; распределение размеров рядом с количеством; комфортные +/- и ручной ввод; сверка итогов; фиксированные Назад / Далее. Сохранить восстановление и безопасный повтор исходного запроса.
4. Спецификация: адаптивные карточки строк на телефоне без обрезки сумм; основное действие связано с фактической партией. Старые спецификации сохраняют действующее распределение доступного количества; копирование второстепенно, повтор обычной модели идёт в общий мастер.
5. Доступные действия вычисляет сервер по действительным правам, состоянию и производственным фактам. Guard остаётся обязательным для каждого изменения. Исправление стандартных прав owner/director — узкое, идемпотентное, без расширения прав сотрудников/индивидуальных ролей и без изменения данных партий.
6. Обычный путь одного цеха не требует материалов, закупок, поставщиков или отдельного меню складов. Приёмка факт / качество / закрытие — разные операции. Отмена и откат из меню с причиной и понятным объяснением, без технических permission-кодов в пользовательском сообщении.

## Приёмка работы

- Реальные Chromium mobile 390×844 и desktop; визуальное сравнение трёх экранов с утверждённым макетом. Проверка ширин 320/390/430, закрепления кнопок и доступа к последнему полю, включая экранную клавиатуру через изменение viewport.
- Цепочка модель → партия/спецификация → пошив → фактическая приёмка → качество → закрытие; новый и старый заказ, архив/восстановление, отдельный черновик.
- Роль owner с отсутствующими стандартными грантами, оператор без cancel, чужая компания, повтор сети, неизменяемая история.
- Lint, typecheck, тесты, сборка, CI; отдельная Railway preview перед production. В production только чтение и исправление стандартных RBAC-грантов, без тестовых партий.
- Отдельная самопроверка итогового diff и отчёт публикации. Разрешение владельца на эту реализацию и публикацию получено в текущей задаче.

## Повторная проверка владельца и связанный путь, 2026-10-05

Владелец не заметил изменения и попросил самостоятельно сверить браузер с описанием финального прототипа, исправив расхождения. Это уточняет композицию макета, сохраняя данные и жизненный цикл:

- Полный номер `ПР-год-номер`, видимый цех, реальные миниатюры и двухсегментные плашки `[размер | количество шт.]`. Один-два цвета показаны сразу; три и больше открываются нижним листом (на компьютере боковой панелью).
- Вместо трёх обобщённых фаз — пять коротких этапов Заказ → Пошив → Готовность → Приёмка → Закрытие. Они отображают существующие статусы, не создают новые операции или таблицы. Отмена вне шкалы.
- Создание из Главной, Партий, модели и паспорта — тот же четырёхшаговый мастер поверх исходного экрана. Закрытие возвращает на исходный экран, ввод сохраняется; прямой URL `/new-batch` работает отдельно. Успешное размещение открывает настоящий паспорт, без дополнительных промежуточных страниц.
- Просроченная партия из «Требует внимания» открывает точный паспорт. Настоящий неоплаченный просроченный счёт за пошив открывает Документы его партии; ссылка получена из read-model Reporting. Счета снабжения не добавляются в этот путь. Валюта существующего Finance — сом, она не подменяется рублями из примера.
- Название модели в паспорте открывает её Производство со спецификациями и партиями. Связанная партия возвращает в её паспорт.
- Завершение остаётся явным действием после реальной приёмки и контроля/подтверждения пропуска качества. Переключатель с обещанием свободного включения/выключения несовместим с учётом принятых изделий; пользователь разрешил разрешить расхождения самостоятельно, поэтому фиктивный переключатель не возвращается. Разрешённое исправление стадии доступно из меню и проверяется сервером.

Числа, модель и цех из цитируемого плана — примеры, а не новые записи production. Отчёт проверки: `CONNECTED_MOBILE_VERIFICATION.md`.
