## ✅ Готово

- Аутентификация/RBAC/мультитенантность на уровне API — все 11 доменных модулей.
- Аудит критичных операций (`packages/domain/audit`).
- Каталог/BOM/Contract Manufacturing/Warehouse/Sales/Marketplace Integration/Honest Sign/Finance/Notifications — доменный слой + API поверх всех 11 модулей.
- Telegram: привязка компании и цеха (инвайт-код + `/start`), полностью рабочая.
- Текст в Telegram → предпросмотр ("что понял / что нашёл / чего не хватает") → «Да» (или inline-кнопки "✅ Подтвердить"/"❌ Отменить", 2026-08-02) → черновик заказа → подтверждение → генерация PDF-спецификации → отправка цеху — весь путь работает, покрыт e2e-тестами.
- Document Template Engine: PDF по эталонному образцу, кириллица (Liberation Serif), русский формат чисел, сквозная нумерация спецификаций по договору цеха, линия для росписи (официальный формат — на одной строке с ФИО, выровнена между Исполнителем/Заказчиком), постоянные поля (условия оплаты/способ доставки/подписанты цеха и компании) подставляются из настроек цеха/компании вместо пустых строк.
- Цех → простой текстовый статус-ответ ("готово"/"в работе") обновляет статус заказа **и уведомляет компанию в её Telegram-чате** (2026-08-02) — не нужно запрашивать статус напрямую через API.
- Остатки материалов (`material_stock_items`/`material_stock_movements`, новая подсистема, 2026-08-02): приёмка закупки (`POST /purchase-orders/:id/receive`) увеличивает остаток на складе; предпросмотр заказа в Telegram сравнивает потребность по BOM (норма расхода × отходы × количество) с остатком и предупреждает о нехватке; подтверждение заказа списывает материал со склада автоматически.
- Полный monorepo pipeline (16 пакетов, build/lint/typecheck/test) зелёный на каждом шаге.

## 🔵 После запуска (Version 2)

Явно отложено до реального использования системы, не убрано из планов. Порядок подтверждён владельцем проекта 2026-08-02: Итерация 9 (эта страница) → статус-пайплайн цеха и приёмка на фулфилмент с браком (Баланс производственной партии, ниже) → себестоимость и расчёты с цехом.

- **Баланс производственной партии** (`docs/PRODUCTION_BATCH_LIFECYCLE_ARCHITECTURE.md`) — полный жизненный цикл партии, брак с причинами и местом выявления, способы устранения (дошив/перешив/скидка/списание), обязательства цеха, KPI цехов. Архитектура готова, ждёт утверждения; реализация — Итерация 15, сразу после завершения Итерации 9-10.
- **Себестоимость и расчёты с цехом** (владелец проекта, 2026-08-02, новая бизнес-функция) — полная себестоимость единицы изделия по компонентам (ткань/фурнитура/пошив/доп. расходы); отдельно "документальная сумма" (в спецификации) и "фактическая себестоимость", разница — настраиваемое смещение на уровне модели или цеха (модель переопределяет цех, если задано); наличная доплата — отдельная сущность учёта со статусом (не оплачено/оплачено), не просто вычисление. Требует архитектурного документа перед реализацией (расширяет Finance) — запланировано после Баланса производственной партии.
- **Universal Inbox** (Итерация 13) — обобщение узкого текстового парсера Итерации 7 до полной AI-классификации любых форматов и каналов, включая голосовые сообщения (см. пункт 2 выше).
