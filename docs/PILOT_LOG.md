# Pilot Log — Pilot v1 (Dogfooding)

> Запрошено владельцем проекта явно (2026-08-04): "через две недели этот журнал будет ценнее сотни придуманных улучшений". Ведётся по факту, день за днём, начиная с деплоя. Не архитектурный документ — сырой протокол: что сделали, что сломалось, что мешало, что осталось руками. Решения по доработкам принимаются только после прохождения полного цикла партии (`docs/MASTER_BACKLOG.md`, раздел «Pilot v1»), не по ходу — этот файл только фиксирует факты, не проектирует исправления.
>
> **Разделение с `docs/PILOT_BUGS.md` (уточнено 2026-08-04):** этот файл — вехи и общий ход дня (деплой прошёл, компания создана, партия перешла в статус X). Конкретные проблемы, найденные при работе с системой — метка критичности, что делали/ожидали/произошло, статус исправления — заводятся **только** в `docs/PILOT_BUGS.md`, не здесь и не дублируются. Если запись в этом журнале — по сути баг, перенести её в `docs/PILOT_BUGS.md`.

## Как заполнять

Одна запись на каждое значимое событие (не обязательно раз в день). Формат:

```
### <дата> — <что происходило>

**Сделали:** ...
**Проблема:** ... (если была)
**Исправлено:** ... / **Осталось:** ...
**Что мешало / заняло слишком много времени:** ...
```

Пусто — значит, ничего значимого не произошло, запись не нужна. Не придумывать записи ради заполнения.

## Цели Pilot v1 (напоминание, `docs/MASTER_BACKLOG.md`)

1. Деплой на Railway.
2. Первая настоящая компания (не демо).
3. 2–3 настоящие модели, 2 настоящих цеха.
4. Первая настоящая производственная партия — полный цикл, до денег и логистики.
