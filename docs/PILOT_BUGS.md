# PILOT_BUGS.md — единственный журнал проблем на время Dogfooding

> Запрошено владельцем проекта явно (2026-08-04): «Никаких GitHub Issues. Никаких Backlog. Во время пилота только один журнал.» С этого момента и до завершения Pilot v1 (критерий — раздел `docs/MASTER_BACKLOG.md`, 0.5, «Критерий завершения») это **единственное** место, куда попадает любая проблема, найденная при реальной работе с системой. Не `docs/MASTER_BACKLOG.md`, не GitHub Issues, не устные заметки. `docs/MASTER_BACKLOG.md` возобновляет приём новых пунктов только после того, как этот журнал будет разобран целиком (см. `CLAUDE.md`, правило 10).

## Зачем отдельно от `docs/PILOT_LOG.md`

Разделение ролей, чтобы не дублировать одно и то же в двух местах:

- **`docs/PILOT_LOG.md`** — свободный дневник вех: деплой прошёл, компания создана, партия перешла в следующий статус, что-то заняло много времени. Не структурирован, не про баги конкретно.
- **`PILOT_BUGS.md` (этот файл)** — только проблемы, найденные при работе с системой на реальной партии, в строгом табличном формате, с меткой критичности и статусом исправления. Это рабочий список для приоритизации, не рассказ.

## Правило «никакого Excel»

Дословно (владелец проекта, 2026-08-04): _«Нельзя пользоваться Excel, если ту же операцию можно выполнить в GarmentOS. Даже если в GarmentOS пока неудобнее.»_ Если операция в системе неудобна — это не повод открыть Excel, это повод завести строку в этом журнале с меткой 🟡 или 🟢. Обход через Excel скрывает именно те проблемы, ради обнаружения которых существует Pilot v1.

## Метки критичности

Каждая проблема получает ровно одну метку:

| Метка | Значение                                                                                         |
| ----- | ------------------------------------------------------------------------------------------------ |
| 🔴    | Блокирует проведение партии — без исправления следующий шаг реального процесса невозможен.       |
| 🟡    | Замедляет работу — партию провести можно, но через обходной путь/руками/дольше, чем должно быть. |
| 🟢    | Просто неудобно — не мешает и не замедляет, но раздражает или могло бы быть лучше.               |

**Исправление — всегда сверху вниз**: сначала все открытые 🔴, затем 🟡, затем 🟢. Не браться за 🟢, пока есть открытые 🔴 — даже если 🟢 быстрее исправить.
