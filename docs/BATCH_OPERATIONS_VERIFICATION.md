# Проверка повторов партии, приёмки и расчётов

Дата: 2026-10-10. Решение: ADR 0005. Тестовые данные создаются только в изолированной базе, не в компании владельца.

## Проверено

- Полный набор API: 44 файла, 191 тест прошёл в CI №66; новые операции покрыты 12 API-тестами.
- Web: 9 тестов прошли.
- Схема и сверка старого seed: проверены сохранение ID права, точное время/SQL прежней миграции (LF или исторический CRLF), отказ при изменённом SQL и неполных разрешениях. Прежний hash сохраняется.
- Черновик не показывает подтверждённый долг и не принимает оплату.
- Реальная PostgreSQL 16: исправление 50 → 48 меняет остаток на −2, сохраняет исходный приход; повтор запроса не создаёт второго движения. Защищены устаревшие факты, повтор SKU, резерв, атомарный откат всех строк, права и изоляция компании.
- Сумма соглашения при недостаче не уменьшается. Платежи учитывают копейки; повтор и исправление сохраняют историю. Возврат сверх записанной оплаты запрещён. Старые операции без валюты не выдаются за подтверждённую оплату. Отмена партии сохраняет аванс и позволяет реальный возврат.
- Перед выпуском проверка `deploy-verify.cjs`: миграции, стандартные права, 11 проверок целостности, все счётчики нарушений равны нулю в изолированной базе.
- Браузер Chromium + Playwright, телефон 390px и ноутбук 1440px: повтор 20/30 по размерам → прежняя цена 500 ₽ → Ак Сарай автоматически → независимая новая партия → пошив → готовность → приёмка 50 → поправка 48 → аванс 12 000,50 ₽ → исправление записи.
- Потеря ответа смоделирована после реального успешного серверного POST: браузер получает сетевую ошибку, страница перезагружается, временный отказ прав не стирает UUID, сохранённый запрос повторяется, второй платёж не создаётся.
- После записанного ОТК отдельное исправление приёмки недоступно, причина объясняется.

## Границы проверки

Browser plugin в текущей сессии отсутствует, использован установленный Playwright с Chromium. Проход по изолированному Railway preview использует реальные ответы веб-сервера и API через urllib с проверкой TLS (прямое соединение Chromium не доверяло CA сетевого прокси). Это не проверка физического Safari/iPhone. Авторизованная проверка на production не выполняется, чтобы не создавать фиктивные бизнес-данные владельца.

Не реализованы согласованное исправление ОТК/брака/отгрузок, автоматическое изменение условий соглашения и банковские переводы. Старые неоднозначные платежи требуют ручной сверки. Восстановление отправленного запроса работает на том же устройстве и аккаунте.

Доказательства браузерного прохода сохраняются отдельно от кода: `garmentos-repair-verification/batch-workflow/` (скриншоты и results.json). Ссылка на PR и подтверждённые версии Railway добавляются в отчёт выпуска после наблюдения SUCCESS.
