# GarmentOS — UI Prototype v2

Отдельный дизайн-прототип. **Рабочий `apps/web` не тронут ни одной строкой.**

## Как открыть

```bash
open apps/design-prototype/index.html      # macOS
xdg-open apps/design-prototype/index.html  # Linux
```

Просто двойной клик по `index.html` — сборка не нужна, зависимостей нет.

Переключение экранов — по клику в боковом меню (десктоп) или нижней панели (мобильный). Прямая ссылка на экран: `index.html#passport`, `index.html#states` и т.д.

## Что проверить

| Ширина | Что должно быть |
|---|---|
| 375–414 | Нижняя панель, одна колонка, карточки вместо таблиц, sticky-кнопка действия, разделы паспорта отдельными экранами |
| 768 | Sidebar сворачивается в rail (только иконки), появляются таблицы, метрики в 4 колонки |
| 1024–1440 | Полный sidebar, паспорт партии в две колонки, вся ширина используется |

Это **один и тот же markup** — не три отдельных макета. Перетаскивайте край окна браузера, композиция перестроится.

## Файлы

| Файл | Что внутри |
|---|---|
| `tokens.css` | Дизайн-токены: цвета, spacing, типографика, радиусы, слои. Переносятся в `apps/web` механически |
| `app.css` | Компоненты и responsive-правила |
| `screens.js` | Разметка экранов |
| `data.js` | Демо-данные — **только реальные поля API**, см. ниже |
| `app.js` | Мини-роутер |
| `shots.mjs` | Скриншоты + автопроверка (скролл, touch targets) |
| `screenshots/` | 63 снимка: 375 / 390 / 414 / 768 / 1024 / 1280 / 1440 px |

## Про данные

Значения в `data.js` условные (это прототип), но **структура настоящая**: каждое поле соответствует реальному полю API GarmentOS. Ни одного выдуманного статуса, метрики или раздела.

Где данных в системе нет — стоит честный Empty State с объяснением, а не нарисованная таблица. Полный список расхождений с макетом — `docs/UI_UX_REDESIGN_PLAN.md` §11.

## Перезапуск проверки

```bash
node apps/design-prototype/shots.mjs
```

Проверяет на всех ширинах: горизонтальный скролл, выход элементов за viewport, размер touch targets (≥32px).
