# PROJECT_VISION.md — Видение проекта GarmentOS

> Этот документ отвечает на вопрос «зачем мы это делаем» и служит источником истины для приоритизации всех решений — продуктовых, архитектурных и технических. Если решение конфликтует с этим документом — пересматривается решение, а не документ (либо документ обновляется осознанно, через ревью).

## 1. Миссия

**GarmentOS — операционная система для швейного и fashion-бизнеса**, которая связывает в единый цифровой контур весь путь изделия: от закупки ткани и фурнитуры, через технологическую подготовку и производство, до склада, продаж на маркетплейсах и в опте, обязательной маркировки «Честный Знак» и финансового учёта.

Миссия: **убрать разрыв между технологом, производством, складом, продажами на маркетплейсах и бухгалтерией**, который сегодня закрывается экселем, тетрадками и ручной сверкой — и который стоит швейным компаниям денег, времени и качества решений.

GarmentOS не пытается быть «ещё одной CRM» или «ещё одним 1С». Мы фокусируемся на **специфике швейного/fashion-производства**: матрица размер×цвет, спецификации (BOM), техкарты, партии кроя, маркировка «Честный Знак», мультиканальные продажи (WB, Ozon, Яндекс Маркет, опт, розница).

## 2. Проблема, которую решает GarmentOS

Швейные компании и fashion-бренды малого и среднего размера сегодня управляют бизнесом через разрозненные инструменты:

| Область | Как это делается сейчас | Что не так |
|---|---|---|
| Учёт тканей/фурнитуры | Excel, блокноты закупщика | Нет привязки к остаткам, закупка «на глаз» |
| Технология/спецификации | Бумажные техкарты, файлы у технолога | Знания не формализованы, теряются при увольнении |
| Производство | Устные договорённости с цехом/подрядчиком | Нет прозрачности по срокам и себестоимости партии |
| Склад | Excel-остатки, физический пересчёт | Расхождения факта и учёта, пересорт по размерам |
| Продажи на маркетплейсах | Личный кабинет WB/Ozon по отдельности | Нет единой картины остатков, цен, заказов |
| Честный Знак | Отдельный кабинет ГИС МТ, ручной ввод | Риск штрафов и блокировки продаж за ошибки маркировки |
| Финансы/себестоимость | 1С отдельно от всего остального | Директор не видит реальную маржу по модели/размеру/каналу в моменте |

Итог: **директор не видит бизнес целиком**, решения принимаются с задержкой и без данных, а рутинные сверки съедают время ключевых людей.

## 3. Кто пользователи GarmentOS

| Роль | Что делает в системе | Ключевая боль, которую снимаем |
|---|---|---|
| **Директор / собственник** | Сводная аналитика: маржа по моделям/каналам, план vs факт, денежный поток | «Не вижу картину бизнеса в моменте, узнаю о проблемах постфактум» |
| **Бухгалтер** | Себестоимость, движение денег, документы, выгрузка в 1С/ФНС | «Свожу цифры руками из пяти источников» |
| **Закупщик** | Заявки поставщикам, остатки тканей/фурнитуры, точка перезаказа | «Закупаю на глаз, то дефицит, то замороженные деньги в остатках» |
| **Технолог** | Спецификации (BOM), техкарты, нормы расхода, версии моделей | «Знания только у меня в голове и в бумажных техкартах» |
| **Менеджер маркетплейсов** | Карточки товаров, цены, остатки, заказы по WB/Ozon/ЯМ в одном месте | «Переключаюсь между 3-5 личными кабинетами, теряю время и ошибаюсь» |
| **Кладовщик** | Приёмка, отгрузка, инвентаризация, остатки по SKU (размер×цвет) | «Физический остаток не сходится с учётным» |
| **Менеджер производства / мастер цеха** | Пошивочные заказы, этапы (крой/пошив/ОТК/упаковка), сроки | «Нет прозрачности, где сейчас партия и когда будет готова» |
| **Менеджер по продажам (опт/розница)** | Заказы B2B/B2C вне маркетплейсов, прайс-листы | «Веду сделки в отдельном мессенджере/экселе» |

Роли — это не жёсткие должности, а **зоны ответственности**: в маленькой компании один человек может закрывать 2-3 роли, система должна поддерживать оба сценария.

## 4. Цели

### Горизонт 1 год (MVP → первые платящие/использующие компании)
- Работающий сквозной цикл: справочники материалов → BOM → производственный заказ → склад (SKU по размеру/цвету) → интеграция с одним маркетплейсом (Wildberries) → базовая себестоимость.
- 3-10 пилотных швейных компаний используют GarmentOS как основной инструмент учёта остатков и заказов.
- Модуль «Честный Знак» покрывает базовый сценарий: получение кодов, нанесение, вывод из оборота при продаже.
- Архитектура выдерживает рост без переписывания ядра (модульный монолит, готовый к выделению сервисов).

### Горизонт 3 года (масштабирование, полнота продукта)
- Полное покрытие мультиканальных продаж: Wildberries, Ozon, Яндекс Маркет, опт, розница/своя витрина — в едином окне.
- Производственное планирование и загрузка мощностей (собственный цех + подрядчики).
- Финансовый модуль закрывает управленческий учёт (P&L по моделям, каналам, партиям) с выгрузкой в 1С.
- BI-аналитика и прогноз спроса (базовый forecasting по истории продаж и сезонности).
- GarmentOS — SaaS-продукт с мультитенантностью, самостоятельная регистрация и онбординг новых компаний.
- 100+ активных компаний-клиентов.

### Горизонт 5 лет (зрелый продукт, отраслевой стандарт)
- GarmentOS — узнаваемое отраслевое решение для швейного/fashion-бизнеса в РФ и СНГ.
- Экосистема интеграций: логистические операторы (СДЭК, Boxberry), банки/эквайринг, доп. маркетплейсы, 1С, ЭДО.
- ML-модели: прогноз спроса, оптимальная точка перезаказа тканей, рекомендации по ценообразованию на маркетплейсах.
- Мобильные приложения для склада (сканирование, инвентаризация) и технолога (работа с техкартами оффлайн).
- Открытый API и партнёрская программа для интеграторов.

## 5. Критерии успеха проекта

Проект считается успешным, если:

1. **Точность остатков**: расхождение учётных и фактических остатков на складе клиента < 2% после 3 месяцев использования.
2. **Скорость принятия решений**: директор получает сводную маржинальность по модели/каналу без обращения к бухгалтеру — данные доступны в системе онлайн.
3. **Снятие рутины**: время на ручную сверку заказов маркетплейсов сокращается более чем на 70% по сравнению с ручным ведением через личные кабинеты.
4. **Комплаенс**: 0 блокировок продаж на маркетплейсах из-за ошибок маркировки «Честный Знак» у пользователей системы.
5. **Retention**: компания, начавшая пользоваться GarmentOS, не возвращается к Excel/бумаге для тех процессов, которые уже покрыты продуктом (проверяется через usage-метрики).
6. **Техническое здоровье**: добавление новой интеграции (например, новый маркетплейс) не требует переписывания ядра — только нового адаптера (проверяется архитектурным ревью).

## 6. Границы: что входит в первую версию (MVP), а что — позже

### Входит в MVP (Фаза 1, см. `docs/ROADMAP.md`)
- Справочники: материалы, поставщики, товары/модели, SKU (размер × цвет).
- BOM (спецификации расхода материалов на модель).
- Простые производственные заказы (без сложного планирования мощностей).
- Склад: приёмка, отгрузка, остатки по SKU, инвентаризация.
- Продажи: заказы вручную + интеграция с одним маркетплейсом (Wildberries: остатки, цены, заказы).
- Базовая себестоимость (материалы + нормативные трудозатраты).
- Пользователи, роли, права доступа (RBAC) под описанные выше персоны.
- Модуль «Честный Знак» — MVP-уровень: учёт кодов маркировки и их статусов.

### Осознанно откладывается (Фаза 2+)
- Полноценное производственное планирование (загрузка мощностей, Ганта, подрядчики).
- Мультиканальность «из коробки» (Ozon, Яндекс Маркет, своя витрина) — архитектурно закладывается сразу, но реализуется поэтапно.
- Финансовый модуль полного цикла (P&L, cash flow, бюджетирование) и выгрузка в 1С.
- BI/аналитика, прогноз спроса, ML-рекомендации.
- Мультитенантный SaaS-онбординг (self-service регистрация компаний).
- Мобильные приложения.
- ЭДО, интеграции с логистикой и банками.

### Не входит в продукт (осознанно вне скоупа)
- Полноценная бухгалтерская/налоговая отчётность (мы не заменяем 1С:Бухгалтерию, мы интегрируемся с ней).
- HR/кадровый учёт, расчёт зарплаты.
- CRM для маркетинга/лидогенерации за пределами продаж.
